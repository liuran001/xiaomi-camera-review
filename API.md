# Camera Review API

Same-origin JSON API under `/api`. Run `gunicorn --workers 1 --threads 4 --bind 0.0.0.0:8090 camera_review.web:app` and one `python -m camera_review.worker`. `APP_PASSWORD` and `SESSION_SECRET` must be supplied; startup fails if absent. Web never launches decoders. Worker uses `/data/worker.lock` to exclude a second worker.

All timestamps are Unix seconds. Filename timestamps use `SOURCE_TZ` (default `Asia/Shanghai`); UI clock times, entered dates/times, and API day filters use fixed Beijing UTC+08:00, never the browser timezone. Clip `date` remains the filename-derived source start date. All IDs are 32 lowercase hex characters, generated internally. No request accepts a filesystem path. Channels are camera-relative directory plus prefix, e.g. `camera-A / 00`, distinct from `camera-A / 10`.

## Authentication and errors

`GET /` and `/static/*` are public login UI assets; all `/api/*` except login require the session cookie, otherwise JSON `401 {"error":"请先登录"}`. The cookie is `HttpOnly; SameSite=Strict` and session-only. Set `COOKIE_SECURE=1` only behind HTTPS; private-network HTTP needs the default `0`. No CORS is exposed.

Every POST including login requires `Origin` with an http(s) authority exactly matching the request `Host`; missing or mismatched Origin returns 403. CLI clients must send e.g. `Origin: http://localhost:8090`. Login and preview additionally require JSON content type (415 otherwise). Other failures return `{"error":"..."}`: 400 invalid input, 404 unknown ID/cache, 409 unstable/changed/unavailable source. Range failures use Flask/Werkzeug 416. Login limits each direct client IP to eight failed attempts per 60 seconds per web process, then returns 429; deployment runs one web process. Use the independent endpoint through a private network or an authenticated HTTPS gateway.

| Method and path | Request / response |
| --- | --- |
| `POST /api/login` | JSON `{"password":"..."}` → 200 `{"ok":true}` + cookie; wrong password 401. Constant-time byte comparison. |
| `POST /api/logout` | `{}` → 200 `{"ok":true}`, clears session. |
| `GET /api/status` | Object described below. |
| `GET /api/days` | Array of Beijing dates descending: `["2026-10-17"]`. Includes every day reached by a clip's known playable interval, even if no file starts that day. |
| `GET /api/channels` | Array of channel strings ascending. |
| `GET /api/clips?date=2026-10-17&channel=camera-A%20%2F%2000` | Array ordered by source start ascending; both filters optional. A date includes clips whose playable interval intersects that Beijing day, including clips starting the previous day. Intervals are half open; a clip ending exactly at midnight does not cover the next day. Omit `date` to read a channel's complete catalog for continuation. Invalid date rejected. |
| `GET /api/events?date=...&channel=...` | Array of events ordered by source time. Date selects event intervals intersecting that Beijing day, including events from a previous-day clip. Offsets stay relative to the source clip. Empty results do **not** mean no people in unanalysed time. |
| `GET /api/original/<clip_id>` | Authenticated MP4 source, `send_file(..., conditional=True)` supports byte Range (206). Rechecks containment, symlinks, current size and nanosecond mtime; changed source 409. |
| `POST /api/preview` | JSON `{"clip_id":"<id>","offset":42,"seconds":8,"prefetch":false}` → 202 job object, deduplicated by source generation and millisecond offset. Offset must be numeric finite and `0 <= offset < duration`, booleans rejected. Optional `seconds` is an integer 1..30 (default30, booleans rejected); optional `prefetch` is boolean (defaultfalse). Same-offset jobs retain their stored length, including legacy30s caches. Foreground requests promote speculative work. Same request requeues failed/evicted jobs. Optional strict boolean `reuse` defaults to false; true can return a readable ready interval from the same generation containing the requested offset, with at least min(requested seconds, 4 seconds, actual EOF remaining) usable time. The response offset/duration describe that original cached interval: seek to request.offset - response.offset and continue at response.offset + response.duration. With reuse enabled, failed or unusable exact-offset jobs retry using the new requested length; omitted/false preserves legacy same-offset length behavior. |
| `GET /api/preview/<job_id>` | 200 job object, or 409 if source has changed. |
| `GET /api/media/<generated_name>` | Authenticated generated JPEG/MP4, Range supported. Only a reference from the current source generation is served; source stat checked again. Arbitrary names, symlinks, orphan/stale caches rejected. |
| `POST /api/pause` | `{}` → `{"paused":true}`. Stops detection at the next chunk boundary; scans, covers and requested previews continue. |
| `POST /api/resume` | `{}` → `{"paused":false}`. Resumes at durable completed offset. |

The authenticated clip and preview objects expose a read-only opaque `generation` (32 lowercase hex characters). It identifies the source version and changes when source size/mtime changes, while the path-derived clip `id` stays the same. Clients must key local duration observations by `(id,generation)`, retain the shortest known playable boundary for that version across lists and jobs, and discard old playback when a new generation is discovered. A preview reports its job's original generation; serialization refuses a mismatched current source with 409 rather than relabelling old work. The field does not accept a path, grant access, or change existing authentication/source-stat checks.

Clip object: `id,generation,camera,channel,date,start,end,duration,media_duration,playable_duration,status,completed,error,thumbnail_error,progress,thumbnail`. Filename-derived `start,end,duration` remain immutable source evidence. `media_duration` is the FFprobe video duration (format duration fallback), null before probing. `playable_duration=min(duration,media_duration)` when known, otherwise filename duration until probing. Worker probes before processing; unknown/invalid duration fails visibly. `completed` is analysed source seconds within playable_duration, `progress` is 0–100 percent of that playable boundary. The UI shows any filename/actual duration mismatch and seeks only within the actual boundary. `thumbnail` is null or an authenticated `/api/media/<hex>.jpg` URL. Status is `unstable` (size mismatch or observed stability window not reached), `pending` (waiting or partially analysed), `complete`, or `error` (analysis error; exponential retry60s–1h). Cover errors use separate thumbnail_error/retry state and never change analysis status/progress/error. Missing sources are excluded and old generations invalidated.

Event object: `id,clip_id,start_offset,end_offset,score,start,channel,thumb`. Offsets are seconds from clip start, `start` is the clip Unix start, `score` is max person confidence, `thumb` is null or the representative JPEG URL. Samples separated by <=6 seconds merge; ranges include up to four seconds before/after and merge across analysis chunks. No face identity or full motion tracks are produced. No accuracy guarantee is made.

Preview job object: `id,clip_id,generation,offset,status,error,duration,playable_duration,media_duration,url`. Status is `pending`, `processing`, `ready`, or `failed`. `duration=max(0,min(stored_requested_seconds,clip.playable_duration-offset))`. Once probed, requests beyond actual EOF are rejected; jobs queued before probing fail visibly if outside that boundary. `url` is null until ready, then `/api/media/<hex>.mp4`. Default client polls every500ms, starts with8s, prefetches one12s successor when playback starts, then one20s successor, then uses30s successors. Prefetch does not change selection/date until consumed; pending work is promoted at EOF and failed preparation retries in foreground. The client plays H.264/AAC (at most960px width,12fps), adopts measured duration immediately, and requests `offset+duration` until that playable boundary. It then reads the **same camera/channel's full catalog without the date filter** and continues from the source wall-clock end. A clip covering that end resumes at `end-next.start`, skipping duplicated overlap; fully covered and unstable files are skipped. A gap advances to the next playable start with an explicit message. No successor stops playback without changing channels. Original playback uses the same continuation rule. The displayed date follows playback across midnight. Manual previous/next follow the visible filtered list.

The day slider and date/time form locate a Beijing wall-clock instant. Channel priority is the explicit channel filter, then the current clip's channel; without either, the UI asks for a channel. For overlaps, the current clip wins if it covers the target, otherwise the covering playable clip with the latest start wins. A target in a gap advances to the next playable clip; no later clip preserves the current player. Outdated catalog, preview, and date-filter responses cannot replace a newer selection; old media EOF events cannot supersede a pending user jump. In original mode, finite browser metadata duration and natural EOF position can reduce the local playable boundary before continuation, including when the worker has not probed the file; this does not write browser measurements into the catalog. Only the selected day's event thumbnails are requested; reading the full channel catalog does not download historical videos or person images. A brief preparation gap may occur between segments; compatibility playback is not gapless streaming.

Status object: `clip_counts` (status→count), `clip_count`, `completed_seconds`, `total_seconds` (sum of playable durations, filename fallback for sources not probed yet), `filename_seconds` (original filename-duration total), `queue` (preview status→count), `paused`, `heartbeat` (Unix time or null), `worker_alive` (heartbeat<180s), `worker_error` (e.g. missing model), `last_scan` (last **successful** full scan Unix time), `scan_error` (root/directory/file IO failure, null after successful scan), `source_timezone`, `errors` (up to20 analysis `{id,error,retry_at}`), `thumbnail_errors` (independent cover errors, same shape), `detection` (human-readable sampled detection description). A worker heartbeat proves liveness, not analysis completion.

## Worker and storage behavior

`EMPTY_SCENE_GATE` defaults to `0`; set `1` to enable. An optional per-chunk gate compares 160×90 blurred grayscale samples to the last actually inferred negative reference. At least eight pixels differing by at least eight gray levels trigger ordinary inference. Only the top-left 40%×10% clock area is ignored in this comparison; the model receives the entire unmasked frame. Every chunk's first sample and at least every15 source seconds run the model. A person hit extends dense three-second detection for30 seconds. Skipped samples produce no person hits and do not update the negative reference. Chunk retries/files/generations use a fresh gate. This heuristic may miss brief/subtle movement; periodic checking bounds the quiet interval but cannot guarantee absence. Decoding and existing model/threshold remain unchanged. After successful generation-checked progress publication, internal state `analysis_last_chunk` records clip/generation/start/source_seconds, sampled/model/skipped counts, gate_enabled, elapsed_seconds and observed time; metrics failure never fails an already-published chunk. These internal counters are not an added public API field.

Environment defaults: `RECORDINGS_ROOT=/recordings`, `DATA_ROOT=/data`, `MODEL_ROOT=/models`, `SOURCE_TZ=Asia/Shanghai`, `STABLE_SECONDS=180`, `COMPLETE_FILE_BYTES=0` (fixed-size check disabled; set134217728 only for recordings confirmed to be128MiB each), `SAMPLE_SECONDS=3`, `ANALYSIS_CHUNK_SECONDS=60` (hard max60), `SCAN_SECONDS=45`, `HEARTBEAT_FILE` unset (legacy DB heartbeat; compose sets a shared tmpfs path), `FFMPEG=ffmpeg`, `FFPROBE=ffprobe`. Model must be named `object_detection_yolox_2022nov.onnx` in MODEL_ROOT (OpenCV Zoo YOLOX, SHA256`c5c2d13e59ae883e6af3b45daea64af4833a4951c92d116ec270d9ddbe998063`). Model load failures surface in status and retry every60s while playback remains available.

Person detection uses OpenCV DNN ONNX with416×416 input, aspect-preserving BGR float32 pixels0–255, top-left placement and114 letterbox padding, with no normalization or channel swap. COCO class0(person) must be the row's highest class; confidence is objectness×person probability and threshold is>=0.65. Only the maximum person confidence is needed for sampled presence, so boxes/grid decoding/NMS are omitted. The previous MobileNetSSD model was replaced after the real-camera sample missed a seated person; the initial YOLOX0.5 threshold was raised after root verified night-room false positives. Model provenance and its license are provided in third_party/. This change does not establish a general detection-accuracy guarantee.

Paths are resolved relative to the readonly recording root; symlinks and hidden/`@*`/`#recycle` directories are excluded. Two equal size+mtime observations and minimum source age are required. Every source change creates a random immutable generation, removes old events/jobs, resets completed time. Old work cannot publish to the new generation, including when the source changes before the next scan. Scanner gathers observations before changing the catalog: root missing/not-directory, os.walk errors or matching-file stat IO errors abort that pass, preserve all existing records/events/jobs/generations, leave last_scan unchanged, and expose scan_error. Only a fully successful walk reconciles absent files as missing. File endpoints still verify actual source containment/stat and refuse unavailable sources even when their index is preserved. SQLite uses WAL, independent connections,15s busy timeout and transactions; no decoder runs inside a transaction. Worker restart requeues processing previews and preserves completed analysis offsets. Errors back off rather than busyloop.

Foreground previews precede speculative previews. Analysis checks for pending previews each sampled frame and yields without publishing incomplete hits/progress or recording a failure. A new foreground job interrupts speculative encoding and requeues it. Covers and seek remux/probes also support cooperative cancellation. Covers and analysis alternate so historical cover generation cannot starve current-day detection; sources are processed newest first. OpenCV threading is bounded by `OPENCV_NUM_THREADS` (default1, clamp1..4), preview decode/x264 by `PREVIEW_THREADS` (default1, clamp1..4); generic Compose defaults to one inference/preview thread and no CPU affinity, with BLAS/MKL/OMP/filter threads1; one640×360 BGR frame and at most one chunk of hit metadata are retained. Input seeks to the chunk start, `skip_frame=nokey` decodes keyframes, aspect ratio is preserved and padded to640×360, `fps=1/3:eof_action=pass` selects frames before scale/pad to avoid resizing discarded frames and normalizes the sampled stream while retaining a valid1–2s final tail. Offsets are approximate and are not actual decoded PTS; a long GOP can move a sampled image by more than3s. The UI makes no fixed timing guarantee and asks viewers to check from a few seconds earlier. Only decoder exit0 **and at least one complete sampled frame** commits a chunk, bounded by probed playable duration. Zero frames are an analysis error (could be EOF or sparse keyframes), never evidence of no people or successful coverage. Event thumbnails are bounded640×360 JPEGs; only representative images persist after chunk cleanup. This is sampled person presence, and gaps between samples can contain missed people.

Schema upgrade from the initial implementation without measured durations resets old completed offsets/events once, because those offsets may have counted undecodable filename tails. Sources and their original filename timestamps remain untouched. Subsequent restarts retain measured durations and valid completed offsets.

After a successful filesystem observation pass, scan writes commit in batches of at most200 files, followed by a separate missing-file reconciliation transaction. This avoids per-file SQLite fsync overhead on NAS disks while keeping write-lock duration bounded; source generations and source-change invalidation remain transactional within each batch. No transaction includes filesystem traversal or media processing.

All worker media operations use a generation-specific stream-copy seek cache under `/data/seek-cache/<clip_id>-<generation>.mp4`. This rebuilds broken source MP4 seek tables with `-map 0 -c copy -movflags +faststart`; no original streams are reencoded or modified. Requests cannot supply cache names/paths. Copies are built on demand by the single worker, validated for a positive video duration, source-generation/stat checked again, and atomically renamed from `.part.mp4`; a valid current copy is reused. FFmpeg copy is single-threaded with180s timeout. Source download always serves the unchanged original. Seek sidecars are private and cannot be fetched via `/api/media`.

Seek cache budget is512MiB and compatibility MP4 budget is1.5GiB (2GiB combined completed-cache budget). Before copying, the worker removes oldest own seek caches to reserve input size plus16MiB overhead; after copying it enforces512MiB again. A source or remux output larger than512MiB fails visibly rather than creating an oversized permanent cache. Scans remove old-generation/orphan seek copies; startup also removes only own generated partial names. Nonmatching files and symlinks are never deleted. Compatibility cache removes unreferenced/old-generation generated MP4s on successful scans, after jobs and on recovery, then evicts least recently requested/read media first; evicted previews requeue on demand. Temporary in-progress output and persistent JPEG/SQLite storage are separate from completed-cache budgets. Covers use `min(5s,playable_duration/2)` for earlier first display. Source files are never deleted or written.

All media subprocess timeouts expose a short Chinese error; the web maps persisted legacy `timed out after ...` command dumps to `生成画面超时，后台会自动重试`. Full exceptions remain in worker logs. Analysis has a180s watchdog that kills even a decoder blocked in stdout.read; that chunk publishes no progress/events and its provisional images are discarded.

New arrivals require at least two observations, unchanged size+mtime for STABLE_SECONDS of observed wall-clock time, and filesystem mtime age >=STABLE_SECONDS. A positive COMPLETE_FILE_BYTES requires strict equality, including for direct original, preview and cached-media APIs (409 while unready). A preserved old mtime cannot bypass the observation window. Stat changes or reappearance reset the window and generation, removing prior progress/event/preview references. Existing valid stable/completed rows retain generation and analysis on upgrade; legacy unstable rows begin a fresh observed window on their first scan. On Linux the worker scans at startup, then coalesces inotify changes with a minimum SCAN_SECONDS interval (45s by default). Without changes it does not periodically walk recordings. Complete-size unstable clips get a one-shot stability deadline check; incomplete stalled uploads wait for another notification. Watch failures fall back to periodic scans and retry notification coverage. Eligible clips are scheduled regardless of camera upload cadence. Source files remain read-only.
